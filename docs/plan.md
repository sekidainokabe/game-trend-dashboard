# 作業計画（承認済み 2026-11-24）

日程は決めず、最速で進める。

## 何を作るか

Steam で今遊ばれているゲームの人数・価格・評価・発売予定を毎時集め、グラフで見られるダッシュボード。位置づけは「企画・営業の担当者が市場の動きを見るための社内ツール」。

- 閲覧はログインなしでできる（URL を開いた瞬間に中身が分かるように）
- ログインすると、ウォッチリストと管理画面が使える

## 構成（B 案：費用ほぼ0円）

- DB：Supabase の無料枠（PostgreSQL、容量 500MB まで）
- 毎時の取得：GitHub Actions の定期実行で、Laravel のコマンドを動かす
  - 定期実行は数分遅れたり、まれに抜けたりする前提で作る（抜けた時刻はグラフ上で空白にする）
  - 非公開リポジトリでは定期実行が動かないという報告があるため、動かなければリポジトリを公開する
- 画面と API：Railway（必要なときだけ起動。master-studio と同じ運用）
- 容量の見積もり：毎時の人数は 200本 × 24回 × 365日 ≒ 175万行/年。毎時の生データは90日で間引き、1日ごとの集計を残す

## データの取り方（2026-11-24 に確認）

| 情報 | 取り先 | 頻度 | 確認結果 |
|---|---|---|---|
| 人気上位100本 | Steam 公式 `ISteamChartsService/GetMostPlayedGames`（キー不要） | 毎日 | 取れる |
| 今遊んでいる人数 | Steam 公式 `ISteamUserStats/GetNumberOfCurrentPlayers`（キー不要） | 毎時 | 取れる |
| 価格・割引率、ジャンル、発売日、Metacritic、レビュー件数、画像 | Steam ストアの `api/appdetails`（非公式・説明書なし） | 毎日 | 取れる。回数制限があるため間隔を空ける |
| レビューの好評率 | Steam ストアの `appreviews` | — | 使えない（トップページへ転送される）。評価は Metacritic と RAWG の点数で代える |
| 発売予定、ジャンル、対応機種、評価、画像 | RAWG（キーあり、非商用・月2万回まで） | 毎日 | ステップ1で確認 |

- RAWG を使うページには、RAWG の表記とリンクを載せる
- 画像は保存せず、API が返す URL をそのまま表示する。画面の下に「画像の権利は各権利者に帰属します」と載せる

## 画面

ホーム（合計人数、急上昇、上位10本とサムネイル・7日間の小さなグラフ、近日発売）、ランキング、ゲーム詳細（人数の推移とセール期間の重ね表示）、ジャンル比較、評価×人気の散布図、発売予定カレンダー、ウォッチリスト、管理（取得の実行結果、追跡するゲーム、ユーザー）。グラフは Recharts。

## 主な表

`games`、`genres`／`platforms` と中間表、`player_snapshots`（毎時の人数）、`daily_stats`（1日ごとの集計）、`fetch_runs`（取得の実行記録）、`users`、`watchlists`、`audit_logs`

## 面接で話すサーバー側の設計判断

1. 自分でデータをためる理由（API は「今」しか返さない）
2. 生データと1日ごとの集計の二層
3. 外部 API の失敗に強い取得（時間切れ・再試行、一部失敗でも止めない、同じ時刻を2回取っても重複しない、実行記録）
4. API の利用枠の管理（RAWG 月2万回、Steam の回数制限）
5. Steam と RAWG の名寄せ
6. 大きな表の索引と保存期間（無料枠 500MB に収める）
7. 閲覧のキャッシュ（100人が同時に開いても DB への問い合わせを増やさない）
8. 費用ほぼ0円の構成にした理由と、その代わりに受け入れたこと（定期実行の遅れ・抜け）
