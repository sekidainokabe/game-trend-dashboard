# 使いやすさ（アクセシビリティ）の確認

目標は WCAG 2.1 の AA です。自動で確かめられるものはテストにし、自動では確かめられないものは手で確かめました（2026-11-25）。

## 自動のテスト（`npm test` で毎回動く）

| テスト | 確かめること |
| --- | --- |
| `src/a11y.test.tsx` | 9ページを仮のデータで描き、axe-core で WCAG 2.1 A・AA の規則（画像の代替テキスト、フォームのラベル、見出しの順、ボタンの名前、ARIA の使い方など）に反していないか。検査が働いていることも、わざと違反を入れた例で確かめる |
| `src/contrast.test.ts` | `index.css` の色の変数から、明るい表示・暗い表示それぞれで、文字は 4.5:1、グラフの線や点は 3:1 以上のコントラストがあるか |

jsdom（テストで使う、画面を持たないブラウザの代わり）では色を計算できないため、axe-core のコントラストの規則は外し、代わりに `contrast.test.ts` で CSS の色から計算しています。

### 見つかって直したもの

- **増加を表す緑（#16a34a）**：白い背景で 3.3:1 しかなく、文字には薄すぎました → #15803d（5.0:1）に変えました。
- **「一部失敗」などの注意の文字**：セールの札の背景用の黄色（#f59e0b）を文字にも使っていて 2.1:1 でした → 文字用に `--warn`（#b45309）を分けました。
- **グラフの「その他」の灰色**：白い背景で 2.5:1 でした → #6b7280 に変えました。
- **増減が「—」のときの文字**：透明度を下げて薄くしていたのをやめました。
- **フッターの文字**：暗い表示で 3:1 しかなかった固定の灰色を、文字の色の変数に変えました。

## 手で確かめたこと

- **スマホの幅（375px）**：9ページとも画面全体が横にはみ出さないこと。上のメニューは縦に潰れていたので、2段目に回して横にスクロールできる1列にしました。列の多い表は、表だけが横にスクロールします。
- **グラフ**：グラフの図は読み上げソフトでは読めないため、グラフごとに `role="img"` と、内容を文にした説明（最大・最小・最新の人数、月ごとの本数など）を付けました。数値はそれぞれ表や一覧でも見られます。
- **色だけに頼らない**：増減は ▲▼ と符号（+12.5%）でも示し、取得の結果は「成功」「一部失敗」などの文字の札で示します。
- **キーボード**：並べ替えは列の名前のボタンで、今の並び順は `aria-sort` で伝えます。期間・軸の切り替えは `aria-pressed` 付きのボタンです。ページを移ると本文の先頭にフォーカスを移し、「本文へ移動」のリンクもあります。
- **画像**：ゲームの画像は名前を隣に文字で出しているため、装飾として `alt=""` にしています。
